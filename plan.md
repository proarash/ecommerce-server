# E-Commerce Server Implementation Plan

## 1. System Overview & Architecture
- **Framework & Core Libraries**: Go, Gin web framework, GORM ORM, PostgreSQL database, Gorilla WebSocket (`github.com/gorilla/websocket`), Swagger API documentation (`github.com/swaggo/gin-swagger`, `github.com/swaggo/files`), MinIO Go SDK (`github.com/minio/minio-go/v7`) for object storage media handling, Zibal IPG payment gateway integration, bcrypt for password hashing, JWT (`github.com/golang-jwt/jwt/v5`) for authentication, Telegram Bot API (HTTP client calls) for event notifications.
- **Access Control & User Separation**:
  - Staff / Admin roles (`admin`, `storekeeper`, `accountant`, `marketer`, `support`) are managed in the `staff_users` table alongside the initial Admin.
  - End-customers / normal users are isolated in the `users` table.
  - JWT token payload contains `user_id`, `role`, and mobile/identity info, enabling unified authentication and role guards.
- **Media & Object Storage**: MinIO integration providing asset storage and presigned/public URLs for products, categories, blogs, avatars, and site content.
- **Cart & Orders**: Dedicated `Cart` and `CartItem` entities linked to users, with checkout transitioning carts into `Order` and `OrderItem` records.
- **Support Chat, Notifications & Telegram Bot**:
  - Real-time chat system with 3 message roles: `bot`, `support`, `user`.
  - The `bot` emits automated system messages for lifecycle events (invoice issued, pre-invoice created, payment succeeded, payment failed).
  - A reusable notification/message dispatch function receives message parameters and dispatches in-app chat notifications and parallel Telegram messages via the Telegram Bot API (`TELEGRAM_BOT_TOKEN`).
  - Notification entity with full CRUD operations accessible by `admin`.
- **Payment Gateway**: Zibal IPG integration (`https://gateway.zibal.ir`) for online checkout, callback verification, and inquiry.
- **Inventory Management**: Built-in inventory tracking (stock levels, inbound/outbound movements, logs) handled internally within the application.

## 3. Roles & Permissions Matrix
| Role | Accessible Sections & Capabilities |
| :--- | :--- |
| **Admin** | Full system access to all endpoints. Manages staff in `staff_users` table (`storekeeper`, `accountant`, `marketer`, `support`, prevents duplicate Admin). Full CRUD on notifications. |
| **Storekeeper** | Product catalog management (Products with unique titles, hierarchical categories, media attachments). Internal inventory tracking (inbound, outbound, stock audit logs). |
| **Accountant** | Financial management: sales analytics (daily, weekly, monthly, annual reports), manual & automated pre-invoices, payment transaction inquiry. |
| **Marketer** | CMS & Marketing: Blog posts (SEO fields, multiple media attachments), banners (with media and `alt_name`), static site content (H1 titles, footer links, descriptions). |
| **Support** | Read-only access to customer orders and pre-invoices. Customer live chat support (Gorilla WebSocket), answering user inquiries. |
| **User (Customer)** | Separated in `users` table. Manage personal profile (name, mobile, address, lat, long; no avatar upload), active cart management, order placement, personal pre-invoices, customer live chat inbox (receives automated bot notifications for payments and invoices). |

## 4. Data Models & Entity Relationships (PostgreSQL / GORM)

> [!NOTE]
> All entities embed `gorm.Model` (providing `ID uint`, `CreatedAt time.Time`, `UpdatedAt time.Time`, and `DeletedAt gorm.DeletedAt` for soft deletes).

### 4.1 Media Management (`internal/media`)
- **`Media` Table**:
  - `gorm.Model`
  - `URL` (`string`): MinIO storage object URL or path
  - `MediaType` (`string`): Enum (`image`, `video`, `document`)
  - `MimeType` (`string`): e.g. `image/jpeg`, `image/png`, `video/mp4`
  - `FileSize` (`int64`): File size in bytes
  - `FileName` (`string`): Original uploaded file name

### 4.2 Staff Users & Customer Users
- **`StaffUser` Table (`internal/staff`)**:
  - `gorm.Model`
  - `Name` (`string`)
  - `Mobile` (`string`, unique, indexed)
  - `Password` (`string`, bcrypt hash)
  - `Role` (`string`, indexed): Enum (`admin`, `storekeeper`, `accountant`, `marketer`, `support`)
  - `AvatarMediaID` (`*uint`): Optional foreign key to `Media`
  - `AvatarMedia` (`*Media`): Belongs to Media
  - `DefaultAvatarID` (`*int`): Static default avatar ID between 1 and 5 (`1`, `2`, `3`, `4`, `5`) representing preset frontend avatars (documented in Swagger)
  - `Status` (`bool`, default: `true`)
- **`User` Table (`internal/user`)**:
  - `gorm.Model`
  - `Name` (`*string`)
  - `Mobile` (`string`, unique, indexed)
  - `Password` (`string`, bcrypt hash)
  - `TelegramChatID` (`*int64`, indexed): Customer's Telegram chat ID for bot notifications
  - `Address` (`*string`)
  - `Latitude` (`*float64`), `Longitude` (`*float64`)
  - `Status` (`bool`, default: `true`)
  *(Note: Regular users do not have custom avatars)*

### 4.3 Catalog, Hierarchical Categories & Media (`internal/product`)
- **`Category` Table**:
  - `gorm.Model`
  - `Name` (`string`)
  - `Slug` (`string`, unique, indexed)
  - `ParentID` (`*uint`, indexed): Self-referencing foreign key for nested/child categories (`nil` for root categories)
  - `Parent` (`*Category`): Belongs to parent category
  - `Children` (`[]Category`): Has many child categories (`foreignKey:ParentID`)
  - `MediaID` (`*uint`): Each category has at most one media
  - `Media` (`*Media`): Belongs to Media
  - `Products` (`[]Product`): Has many products
- **`Product` Table**:
  - `gorm.Model`
  - `Title` (`string`, unique, indexed): Product name is strictly unique
  - `Description` (`string`)
  - `Price` (`float64`)
  - `SKU` (`string`, unique, indexed)
  - `IsActive` (`bool`, default: `true`)
  - `CategoryID` (`uint`, indexed): Belongs to exactly one Category
  - `Category` (`Category`)
  - `Media` (`[]Media`): Many-to-many relationship via join table `product_media` (supporting multiple images and videos per product)
  - `Attributes` (`[]Attribute`): Many-to-many relationship via join table `product_attributes`
- **`Attribute` Table**:
  - `gorm.Model`
  - `Key` (`string`, unique, indexed)
  - `Title` (`string`)
  - `Name` (`string`)
  - Created independently and assignable to any product

### 4.4 Cart & Cart Items (`internal/cart`)
- **`Cart` Table**:
  - `gorm.Model`
  - `UserID` (`uint`, unique, indexed): Each customer has one active cart (`User` has one `Cart`)
  - `Items` (`[]CartItem`): Has many cart items
- **`CartItem` Table**:
  - `gorm.Model`
  - `CartID` (`uint`, indexed)
  - `ProductID` (`uint`, indexed)
  - `Product` (`Product`)
  - `Quantity` (`int`, default: `1`)

### 4.5 Orders & Finance (`internal/finance`)
- **`Order` Table**:
  - `gorm.Model`
  - `UserID` (`uint`, indexed): Belongs to customer `User`
  - `Status` (`string`): Enum (`pending`, `paid`, `cancelled`, `processing`, `delivered`)
  - `TotalAmount` (`float64`)
  - `Items` (`[]OrderItem`): Has many order items
- **`OrderItem` Table**:
  - `gorm.Model`
  - `OrderID` (`uint`, indexed)
  - `ProductID` (`uint`, indexed)
  - `Product` (`Product`)
  - `Quantity` (`int`)
  - `UnitPrice` (`float64`)
- **`PreInvoice` Table**:
  - `gorm.Model`
  - `OrderID` (`uint`, indexed)
  - `UserID` (`uint`, indexed)
  - `InvoiceNumber` (`string`, unique, indexed)
  - `Amount` (`float64`)
  - `IssuedBy` (`string`): Staff user or system
  - `Status` (`string`): Enum (`issued`, `paid`, `cancelled`)
- **`PaymentTransaction` Table (`internal/payment`)**:
  - `gorm.Model`
  - `OrderID` (`uint`, indexed)
  - `UserID` (`uint`, indexed)
  - `Amount` (`int64`, in Rials)
  - `TrackID` (`int64`, unique, indexed)
  - `Status` (`int`)
  - `Result` (`int`)
  - `RefNumber` (`*int64`)
  - `CardNumber` (`*string`, masked)
  - `Description` (`string`)
  - `PaidAt` (`*time.Time`)

### 4.6 Inventory Tracking (`internal/inventory`)
- **`InventoryStock` Table**:
  - `gorm.Model`
  - `ProductID` (`uint`, unique, indexed)
  - `Quantity` (`int`, default: `0`)
  - `WarehouseLocation` (`*string`)
- **`InventoryLog` Table**:
  - `gorm.Model`
  - `ProductID` (`uint`, indexed)
  - `Type` (`string`): Enum (`inbound`, `outbound`)
  - `Quantity` (`int`)
  - `Reason` (`string`)
  - `CreatedBy` (`uint`): Staff user ID who recorded the movement

### 4.7 CMS, Marketing & Site Settings (`internal/cms`)
- **`BlogPost` Table**:
  - `gorm.Model`
  - `Title` (`string`)
  - `Slug` (`string`, unique, indexed)
  - `Description` (`string`)
  - `Content` (`string`)
  - `SeoTitle` (`string`), `SeoDescription` (`string`), `Keywords` (`string`)
  - `AuthorID` (`uint`)
  - `Media` (`[]Media`): Many-to-many relationship via `blog_media` (multiple images/videos)
- **`Banner` Table**:
  - `gorm.Model`
  - `Title` (`string`)
  - `MediaID` (`uint`): Linked to `Media`
  - `Media` (`Media`)
  - `AltName` (`string`)
  - `LinkUrl` (`string`)
  - `DisplayOrder` (`int`, default: `0`)
  - `IsActive` (`bool`, default: `true`)
- **`SiteContent` Table**:
  - `gorm.Model`
  - `Key` (`string`, unique, indexed)
  - `Value` (`string`)
  - `Description` (`string`)
  - `MediaID` (`*uint`): Optional media attachment (e.g. site logo, favicon, footer graphic)

### 4.8 Chat & Messaging System (`internal/chat`)
- **`ChatRoom` Table**:
  - `gorm.Model`
  - `UserID` (`uint`, indexed): Customer user
  - `SupportID` (`*uint`, indexed): Assigned staff support user
  - `Status` (`string`): Enum (`open`, `in_progress`, `closed`)
- **`ChatMessage` Table**:
  - `gorm.Model`
  - `RoomID` (`uint`, indexed)
  - `SenderRole` (`string`): Enum (`bot`, `support`, `user`)
  - `SenderID` (`*uint`): User ID or Staff ID (nullable for automated `bot` messages)
  - `Message` (`string`)
  - `Type` (`string`, default: `text`): Enum (`text`, `invoice`, `preinvoice`, `payment_success`, `payment_failed`)
  - `Payload` (`*string`): JSON string with additional event data (e.g. invoice number, transaction track ID)

### 4.9 Notifications (`internal/notification`)
- **`Notification` Table**:
  - `gorm.Model`
  - `UserID` (`*uint`, indexed): Specific target customer or null for broadcast
  - `Title` (`string`)
  - `Message` (`string`)
  - `Type` (`string`): Enum (`order`, `payment`, `system`, `promo`)
  - `IsRead` (`bool`, default: `false`)
  - `Channel` (`string`): Enum (`in_app`, `telegram`, `both`)

## 5. Automated Bot Messaging & Telegram Bot Service (`internal/notification`)

### 5.1 Reusable Message Dispatcher Function
- Defined in `internal/notification/service.go`:
  ```go
  type AutomatedMessagePayload struct {
      UserID       uint
      TelegramChatID *int64
      Title        string
      Message      string
      Type         string // invoice, preinvoice, payment_success, payment_failed, support
      ExtraData    map[string]interface{}
  }

  func SendAutomatedMessage(ctx context.Context, payload AutomatedMessagePayload) error
  ```
- **Lifecycle Integration Hooks**:
  - **Pre-invoice issued**: Triggered in `internal/finance` to send pre-invoice link and breakdown.
  - **Invoice issued / Order created**: Triggered on order placement.
  - **Payment Succeeded / Failed**: Triggered in `internal/payment` upon Zibal verification callback.
  - **Support Event**: Triggered when a new ticket/chat inquiry is initiated.
- **Dispatch Channels**:
  1. Inserts a `ChatMessage` into the user's `ChatRoom` with `SenderRole = "bot"`.
  2. Saves a `Notification` entity record for user inbox history.
  3. Sends a Markdown/HTML formatted message via the **Telegram Bot API** (`https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/sendMessage`) to the user's registered `TelegramChatID` or admin notification group.

## 6. Authentication, JWT & Role Authorization

### 6.1 JWT Token Specification (`pkg/token`)
- Claims payload:
  ```go
  type AuthPayload struct {
      UserID   uint   `json:"user_id"`
      Mobile   string `json:"mobile"`
      Role     string `json:"role"` // admin, storekeeper, accountant, marketer, support, user
      UserType string `json:"user_type"` // "staff" or "customer"
      jwt.RegisteredClaims
  }
  ```
- Generated upon successful login for both `staff_users` and regular customer `users`.
- Auth middleware parses and validates the token from the `Authorization: Bearer <token>` header, placing `user_id` and `role` into Gin context (`c.Set("user_id", ...)` and `c.Set("role", ...)`).

### 6.2 Role Guard Middleware
- `RequireRoles(...roles string) gin.HandlerFunc`:
  - Validates if the authenticated role exists in the allowed list.
  - `admin` role has bypass access to all secured endpoints across the system.

## 9. Zibal IPG Payment Gateway Integration (`internal/payment`)
- **Base URL**: `https://gateway.zibal.ir`
- **Merchant**: `ZIBAL_MERCHANT` (use `"zibal"` for sandbox).
- **Callback URL**: `ZIBAL_CALLBACK_URL` or server endpoint (e.g. `https://api.domain.com/api/payment/callback`).
- **Client Redirect URL**:
  - After processing the payment callback on the server, the backend redirects the customer's browser to the frontend client URL with a query parameter containing the formatted order identifier:
    - Format: `?inv=inv-<ORDER-ID>` (e.g. `https://client.domain.com/payment/result?inv=inv-1234`).
    - With this query parameter, the client frontend extracts the order ID directly to fetch the latest order status and receipt details from the backend (`GET /api/user/orders/:id` or `GET /api/payment/status/:trackId`).
- **Workflow**:
  1. `POST /api/payment/checkout/:orderId`: Calls Zibal `/v1/request`, creates `PaymentTransaction` with status `-1` (Pending), returns `trackId` and redirect URL.
  2. Customer completes payment on Zibal gateway.
  3. Gateway redirects customer back to backend callback: `GET /api/payment/callback`.
  4. Server calls Zibal `/v1/verify`:
     - If verified: marks order as `paid`, marks transaction as successful, creates/updates `PreInvoice`, calls `SendAutomatedMessage` with `payment_success`.
     - If failed: marks order as failed, calls `SendAutomatedMessage` with `payment_failed`.
  5. Backend immediately issues an HTTP 302 redirect sending the user to the client app with the query parameter: `?inv=inv-<ORDER-ID>`.

- `GET /api/finance/reports?period=daily|weekly|monthly|annually`: Financial reporting
- `POST /api/finance/preinvoices`: Manual pre-invoice creation

- `POST /api/payment/inquiry/:trackId`: Manual gateway transaction check

- `WS /ws/chat` & `GET /api/support/chat/rooms`: Live support agent console

### Admin Management Area (`role: admin`)
- `POST /api/admin/staff`: Create staff users (`storekeeper`, `accountant`, `marketer`, `support`); supports assigning `AvatarMediaID` or `DefaultAvatarID` (enum integer 1 to 5 for frontend preset avatars); prevents creating duplicate `admin` users

- **Notification CRUD**:
  - `POST /api/admin/notifications`: Create and dispatch notification
